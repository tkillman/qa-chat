# Feature Specification: 관리자 질문답변 목록 조회

**Feature Branch**: `001-admin-qa-list`  
**Created**: 2026-03-05  
**Status**: Draft  
**Input**: User description: "관리자로 로그인 한뒤 현재 등록된 질문과 답변 목록을 페이징 형식으로 확인할 수 있게해줘"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기본 질문답변 목록 조회 (Priority: P1)

관리자가 로그인한 후 등록된 질문과 답변의 전체 목록을 확인할 수 있습니다. 목록은 카드 형식으로 표시되며, 각 카드에는 질문 텍스트와 답변 내용이 포함됩니다. 항목들은 최신 등록순(내림차순)으로 정렬되어 가장 최근에 추가된 항목이 먼저 표시됩니다. 기본적으로 페이지당 10개씩 표시됩니다.

**Why this priority**: 이 기능의 핵심이자 최소 기능 단위입니다. 관리자가 데이터를 확인할 수 있는 기본적인 수단을 제공합니다.

**Independent Test**: 관리자 로그인 후 목록 화면에 접근하여 등록된 Q&A 항목들이 카드 형식으로 페이지당 10개씩, 최신 등록순으로 표시되는지 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 로그인되어 있고 ChromaDB에 25개의 Q&A가 등록됨, **When** 관리자가 목록 화면에 접근, **Then** 첫 페이지에 10개의 항목이 표시됨
2. **Given** 관리자가 로그인되어 있고 ChromaDB에 데이터가 없음, **When** 관리자가 목록 화면에 접근, **Then** "등록된 질문답변이 없습니다" 메시지가 표시됨
3. **Given** 관리자가 로그인되어 있고 ChromaDB에 5개의 Q&A가 등록됨, **When** 관리자가 목록 화면에 접근, **Then** 5개의 항목이 모두 표시되고 페이지 네비게이션이 표시되지 않음

---

### User Story 2 - 페이지 네비게이션 (Priority: P1)

관리자는 이전/다음 버튼을 사용하여 여러 페이지를 탐색할 수 있습니다. 현재 페이지 번호와 전체 페이지 수가 표시되며, 첫 페이지에서는 이전 버튼이, 마지막 페이지에서는 다음 버튼이 비활성화됩니다.

**Why this priority**: P1 스토리와 함께 구현되어야 페이징 기능이 완성됩니다. 데이터가 많을 때 필수적인 기능입니다.

**Independent Test**: 등록된 항목이 20개 이상일 때 이전/다음 버튼으로 페이지 이동이 정상 동작하는지 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 첫 페이지를 보고 있음, **When** 이전 버튼 클릭 시도, **Then** 이전 버튼이 비활성화되어 있거나 동작하지 않음
2. **Given** 관리자가 2페이지를 보고 있음, **When** 이전 버튼 클릭, **Then** 1페이지로 이동하고 해당 페이지의 항목들이 표시됨
3. **Given** 관리자가 마지막 페이지를 보고 있음, **When** 다음 버튼 클릭 시도, **Then** 다음 버튼이 비활성화되어 있거나 동작하지 않음
4. **Given** 관리자가 목록을 보고 있음, **When** 화면 확인, **Then** "페이지 2/5" 형식으로 현재 페이지와 전체 페이지 수가 표시됨

---

### User Story 3 - 페이지당 항목 수 변경 (Priority: P2)

관리자는 페이지당 표시할 항목 수를 10개, 20개, 50개 중에서 선택할 수 있습니다. 선택 변경 시 첫 페이지로 이동하며, 선택한 개수만큼 항목이 표시됩니다.

**Why this priority**: 기본 조회 기능이 없으면 의미가 없지만, 사용자 편의성을 크게 향상시킵니다.

**Independent Test**: 페이지당 항목 수 드롭다운을 변경하여 10, 20, 50개 옵션이 정상 동작하는지 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 목록을 보고 있고 페이지당 10개로 설정됨, **When** 페이지당 항목 수를 20개로 변경, **Then** 첫 페이지로 이동하고 20개의 항목이 표시됨
2. **Given** 관리자가 2페이지에 있음, **When** 페이지당 항목 수를 변경, **Then** 자동으로 1페이지로 이동함
3. **Given** 총 15개의 항목이 등록됨, **When** 페이지당 50개로 설정, **Then** 모든 15개 항목이 한 페이지에 표시되고 네비게이션이 표시되지 않음

---

### User Story 4 - 총 항목 수 표시 (Priority: P3)

관리자는 화면에서 등록된 전체 질문답변 항목의 총 개수를 확인할 수 있습니다. 이 정보는 페이지 네비게이션 영역에 "총 N개의 항목" 형식으로 표시됩니다.

**Why this priority**: 필수는 아니지만 관리자가 전체 데이터의 규모를 파악하는 데 유용합니다.

**Independent Test**: 목록 화면에서 총 항목 수가 실제 등록된 항목 수와 일치하는지 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** ChromaDB에 37개의 Q&A가 등록됨, **When** 관리자가 목록 화면에 접근, **Then** "총 37개의 항목" 메시지가 표시됨
2. **Given** ChromaDB에 데이터가 없음, **When** 관리자가 목록 화면에 접근, **Then** "총 0개의 항목" 또는 "등록된 항목이 없습니다" 메시지가 표시됨

---

### Edge Cases

- **ChromaDB 항목이 없을 때**: "등록된 질문답변이 없습니다" 메시지만 표시, 모든 페이징 네비게이션 요소(페이지 번호, 이전/다음 버튼, 항목 수 선택) 완전히 숨김
- **페이지당 항목 수보다 적은 데이터**: 모든 항목을 한 페이지에 표시, 페이지 네비게이션 버튼 숨김 (총 항목 수는 표시)
- **관리자가 로그인하지 않은 상태**: 목록 화면 접근 차단, 로그인 화면으로 리다이렉트
- **ChromaDB 조회 중 오류 발생**: 사용자 친화적 오류 메시지 표시 ("목록을 불러오는 중 오류가 발생했습니다")
- **매우 긴 질문이나 답변**: 각 카드 내에서 전체 텍스트를 표시하되 스크롤 박스를 사용하여 카드 높이 제한
- **동시에 다른 관리자가 항목을 추가/삭제**: 수동 새로고침 버튼을 클릭하면 최신 데이터 반영, 페이지 이동 시에도 최신 데이터 자동 조회

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 관리자 인증 상태를 확인해야 하며, 로그인하지 않은 경우 목록 화면 접근을 차단해야 함
- **FR-002**: 시스템은 ChromaDB에 저장된 모든 질문과 답변 항목을 조회할 수 있어야 함
- **FR-003**: 시스템은 페이지당 표시할 항목 수를 지원해야 하며, 기본값은 10개여야 함
- **FR-004**: 관리자는 페이지당 항목 수를 10개, 20개, 50개 중에서 선택할 수 있어야 함
- **FR-005**: 시스템은 이전/다음 버튼을 통한 페이지 네비게이션을 제공해야 함
- **FR-006**: 첫 페이지에서는 이전 버튼이, 마지막 페이지에서는 다음 버튼이 비활성화되어야 함
- **FR-007**: 시스템은 현재 페이지 번호와 전체 페이지 수를 "페이지 X/Y" 형식으로 표시해야 함
- **FR-008**: 시스템은 등록된 전체 항목의 총 개수를 표시해야 함
- **FR-009**: 각 항목은 카드 형식으로 표시되어야 하며, 질문 텍스트와 답변 텍스트를 포함해야 함
- **FR-010**: 페이지당 항목 수를 변경하면 자동으로 첫 페이지로 이동해야 함
- **FR-011**: ChromaDB에 항목이 없을 경우 "등록된 질문답변이 없습니다" 메시지를 표시하고, 모든 페이징 네비게이션 요소를 숨겨야 함
- **FR-012**: ChromaDB 조회 중 오류가 발생하면 사용자 친화적인 오류 메시지를 표시해야 함
- **FR-013**: 매우 긴 질문이나 답변은 카드 내에서 전체 텍스트를 표시하되, 스크롤 박스를 사용하여 카드 높이를 제한해야 함
- **FR-014**: 시스템은 항목들을 최신 등록순(내림차순)으로 정렬하여 표시해야 함
- **FR-015**: 시스템은 수동 새로고침 버튼을 제공해야 하며, 클릭 시 ChromaDB에서 최신 데이터를 조회하여 목록을 업데이트해야 함

### Key Entities

- **QA List Item**: 목록 화면에 표시되는 질문답변 항목. 속성: question (질문 텍스트), answer (답변 텍스트), 표시 순서
- **Pagination State**: 페이징 상태 정보. 속성: current_page (현재 페이지 번호), total_pages (전체 페이지 수), items_per_page (페이지당 항목 수), total_items (전체 항목 수)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 로그인 후 3초 이내에 질문답변 목록 화면에 접근하고 첫 페이지를 볼 수 있어야 함
- **SC-002**: 시스템은 1000개의 질문답변 항목이 등록된 상태에서도 페이지 로딩 시간이 2초를 초과하지 않아야 함
- **SC-003**: 관리자가 페이지 네비게이션(이전/다음 버튼)을 사용할 때 페이지 전환이 1초 이내에 완료되어야 함
- **SC-004**: 관리자는 페이지당 항목 수를 변경한 후 1초 이내에 새로운 설정으로 목록을 확인할 수 있어야 함
- **SC-005**: 모든 질문답변 항목이 화면에 읽기 쉬운 형태로 표시되어야 하며, 텍스트가 화면을 벗어나지 않아야 함
- **SC-006**: 관리자가 목록 화면에서 현재 페이지 정보(페이지 번호, 전체 페이지 수, 총 항목 수)를 즉시 파악할 수 있어야 함

## Clarifications

### Session 2026-03-05

- Q: 목록의 정렬 순서 → A: 최신 등록순 (내림차순)
- Q: 긴 텍스트 표시 방식 → A: 전체 텍스트 표시 (스크롤 박스 사용)
- Q: 항목 표시 형식 → A: 카드 형식 (각 항목이 개별 카드로 표시)
- Q: 목록 새로고침 방식 → A: 수동 새로고침 버튼 제공
- Q: 빈 목록 상태에서 네비게이션 요소 표시 → A: 모두 숨김 (메시지만 표시)
